# 右手杯——卡牌赛事一站式平台

这个网站从一场 8 人 BO3 双败的「右手杯」起家,如今是一个通用的卡牌赛事平台:系列赛与多届比赛并存,赛程摆在自由画布上——单败、双败、复活赛或任意自定义对阵拓扑都画得出来。办赛、看赛、交卡组、做海报、投屏都在浏览器里完成,部署后数据存云端,任何设备打开网址看到同一份内容。全站登录墙:未登录只能到登录页(或打开大屏页看到登录提示);用手机号收验证码即可登录,新号码自动注册;管理员在个人页凭码升格,可以创建系列与届、布置赛程、开放报名、发邀请码;选手绑定档案后可自助维护资料、报名参赛、在提交窗口内上报自己的卡组。

> 本项目代码以 [MIT](LICENSE) 许可开源。`icons/classes/` 下的职业图标素材来自《Shadowverse: Worlds Beyond》官网,版权归 Cygames 所有,不在 MIT 许可范围内,仅供个人非盈利赛事使用。

登录后先到总览工作台(index.html):当前对阵、最新战报、接下来三块一眼看清赛事进展;标题旁可切换正在显示的比赛,页面下方的"比赛总览"按系列分组列出全部已创建比赛及其状况(小节头是系列名与届数,无系列的届归入"未分组",点击行即切换),底部是各功能板块的快捷入口。全站配色为 Things 风格色板,浅色/深色双主题。

## 比赛(schedule.html)

主办方的工作台。**赛制不是固定模板,而是自由画布上的对阵图**:对局卡片任意增删、随意摆位,卡片间的带箭头连线决定晋级流向——人数多少、几轮几线、单败双败还是复活交叉,全由主办方自己画(8 人 BO3 双败 14 场、关键场 BO5 只是右手杯最初的一版摆法)。每场对局录的是局数比分,录完即自动结算:下一轮对位、晋级名单与最终名次实时派生,改掉旧比分整条后续链路自动重算,决出终点后显示冠军、亚军、季军。页头的"切换比赛"下拉可以切换查看任意一届,往届比赛也从这里回看。

整个赛程铺在一张无限画布上:对局卡片按 28px 点阵定位(每卡占 10×6 个点,拖拽、方向键逐点微调,可自由摆放),Ctrl/⌘+滚轮缩放,也可以切换成滚轮直接缩放的模式;触屏设备支持单指平移、双指捏合缩放,缩放级别会记住,下次打开不用重新放大。卡片之间的曲线连线标出晋级流向。编辑时画布显示无限延伸的点阵背景并隐藏赛事背景图;连线从卡片连接点拖出——每卡六个连接点,上排默认输出胜者、接入 A 位,下排默认输出败者、接入 B 位,也可在卡片设置里自定义取哪个出口;连线端点随卡片移动自动跟随。编辑过程可以撤销/重做(⌘/Ctrl+Z 与工具栏按钮,保留最近 10 步),误删的对局连同它的比分和卡组一起找回;改动未保存时保存按钮亮圆点,此时关闭页面会弹出确认。画布与赛程列表是同一页的两种视图:顶栏按钮随时切换,列表按阶段分组展示全部场次(桌面查场次更快);窄屏默认进列表(画布缩得太小不可读),选择会记住。

每张卡片下方是职业卡组行:双方各自的职业图标并排,点图标跳转对应的卡组外链。选手没有为某场比赛提交新卡组时,自动继承他上一场的卡组(沿晋级链派生,数据不复制)。

## 选手与账号

- **选手库(players.html)**:管理跨届通用的全局选手——名字、头像、赛前垃圾话、专属颜色、队伍 ID 和队标图。垃圾话和颜色会跟着选手进海报。删除选手不影响历史比赛记录。页头有选手搜索(按名称/队伍 ID 实时过滤,全员可用);新增选手也在页头,仅管理员可见。
- **选手中心(me.html)**:登录用户的自助专区,四个标签页——**我的对局**(卡组提交窗口:管理员在赛事设置里配置提交开关,可设每日循环时段如每天 09:00–17:00 自动开闭,也可随时手动开关;开关开启期间,绑定了选手档案的用户看到自己所有已确定的场次,逐场提交职业、卡组名称和卡组外链,可反复修改;未开始的场次,已提交的卡组对其他人隐藏(画布上显示待公示锁),开关关闭即全员公示;比赛一旦录了比分,该场卡组锁定;没提交的场次沿用继承)、**我的比赛**(自助报名:管理员开放报名后一键报名或取消,已被指派上场的不能自助退赛;开放报名的届在前,已参加过的在后,报名池并入比赛页的"选手名单")、**资料与账号**(升级与绑定:填选手码/管理员码完成角色跃迁;自助修改头像、昵称、队伍 ID、队标、垃圾话和海报颜色,也能改密码、验码绑定手机号;账号名只用于登录,账号昵称与选手展示名随时可改)、**发码中心**(仅管理员可见:生成选手码与查看全部邀请码状态,超级管理员另可发管理员码)。未登录时整页是统一登录引导;侧栏入口与左下角头像按钮都进这里,旧地址(my-decks / my-tourneys / profile)自动跳转到对应标签页。报名不限人数:管理员设"取前 N 人参赛",比赛页右上角选手名单按报名先后编号(开放期间默认展开,重绘自动恢复、手动关闭后不强开;超出 N 的候补弱化);报名关闭后管理员可一键把前 N 名随机填入入场赛(无箭头指入的场次,已指派会被覆盖,入场卡已录比分则拦截)。

账号与权限(2026-08-30 重构一期)分五级,登录方式以手机号短信验证码为主(新号码验码即注册),早期账号的用户名密码登录仍然可用,旧账号也可在个人页验码绑定手机号后双通道登录:

| 能力 | 游客 | 注册用户 | 选手 | 管理员 | 超级管理员 |
|---|---|---|---|---|---|
| 登录/注册(发码验码) | ✓ | — | — | — | — |
| 浏览比赛内容(登录墙内) | ✗ | ✓ | ✓ | ✓ | ✓ |
| 个人页(改昵称/改密/绑手机/填码) | ✗ | ✓ | ✓ | ✓ | ✓ |
| 选手资料自助编辑、报名、卡组提交 | ✗ | ✗ | ✓ | ✓(需绑选手) | ✓(需绑选手) |
| 图片上传 | ✗ | ✗ | ✓ | ✓ | ✓ |
| 布置赛程/录比分/赛事设置 | ✗ | ✗ | ✗ | ✓ | ✓ |
| 发选手码(发码中心) | ✗ | ✗ | ✗ | ✓ | ✓ |
| 发管理员码 | ✗ | ✗ | ✗ | ✗ | ✓ |
| 超管后台(审计/账号/备份/封禁) | ✗ | ✗ | ✗ | ✗ | ✓ |

角色跃迁只走"个人页填码":空白选手码建立新选手档案,绑定选手码继承老选手的全部历史数据(发码即发身份,由发码中心生成);管理员码只有超级管理员能发,填入即升管理员——管理员同时可以绑选手档案,以选手身份参赛。超级管理员由环境变量 `SUPER_ADMIN_USERNAMES` / `SUPER_ADMIN_PHONES`(逗号分隔名单)动态升格,改 env 即生效,也是全新环境的引导通道(第一个命中名单的登录即超管)。

系列与届按**创建者归属**管控(2026-08-31 二期):每个系列和每届比赛都记录 createdBy,新资源由服务端盖章创建者;管理员只能编辑/删除自己创建的系列与届,动他人的或系统预置的(createdBy 为空)会被服务端拒绝——超级管理员不受限。前端与此同口径:打开不是自己创建的届时,编辑、赛事设置等按钮直接隐藏,非归属管理员等同选手视角(只能看),首次进入会有一次性说明;届切换下拉按系列分组展示。选手、报名等其余数据仍由全部管理员共同维护。

全站登录墙以服务端为准:除登录相关、健康检查与测试接口外,所有 `/api/*` 无会话一律 401;前端各页守卫未登录跳转登录页(带 returnTo 回跳),OBS 大屏两页(海报舞台/比分舞台)可匿名打开但数据接口 401 时整页显示登录提示,现场设备登录一次即可(cookie 30 天)。唯一例外是未配置 OSS 的纯本地进程(本地开发):服务端对匿名放行,前端进入本地超管模式——生产(OSS 已配)不适用;E2E 以专用 `YOUSHOUBEI_ENFORCE_WALL=1` 显式压掉该分支以持续测试墙语义。旧的全局管理口令(ADMIN_TOKEN)已彻底退役:代码零引用,前端解锁口令界面删除,管理操作全部凭登录账号的角色放行;上传也相应从"任意登录会话"收紧为"绑选手者或管理员"。

## 超管后台(admin.html)

超级管理员的运维专区,独立页面(侧栏"后台"入口仅超管可见),四个标签:**审计流水**(按月查看全部写操作记录,可按操作者/动作过滤)、**账号与邀请码**(全部账号的角色、绑定选手与邀请码核销状态;手机号一律脱敏显示为 138\*\*\*\*1234)、**比赛状态**(各届的系列归属、创建者与进行状况总览)、**健康与备份**(OSS 存储状态、数据量、备份列表;一键手工快照数据/账号/邀请码三件套,恢复需输入 RESTORE 确认且只能恢复白名单内的 data 类备份,恢复前自动再留一版底)。账号操作支持封禁/解封、管理员↔选手降级与**删除账号**(手机号随账号删除即释放,同号可重新短信注册;绑定的选手档案保留仅解除归属,可经绑定码重新认领;被删者既有会话自然失效;删除为双重确认,需输入表格显示的用户名),但超级管理员(env 名单命中者)与操作者本人不可操作;升超级管理员不在此处,唯一入口仍是 env 名单。对应接口 `/api/admin/*`(users / audit / health / backup / restore / users/:id/status / users/:id/role / users/:id/delete)全部仅超管可调,写操作全部记审计。

## 海报生成器(poster.html)

赛前做 VS 海报。左右选手直接从主站选手库选择,名字、头像、队标、颜色、垃圾话一并带出,也能对颜色做临时微调;比赛信息(名称、阶段、局数、日期、场馆)自由填写。内置 5 种版式(撕裂分屏 / 像素街机 / 极简刊头 / 魔纹华饰 / 赛博霓虹)共 11 套主题,预览和导出共用同一份 SVG,所见即所得,可导出 1080p/2K/4K 的 PNG。"生成 OBS 源"按钮调服务器接口生成短链地址,粘贴到 OBS 的浏览器来源即可在直播中展示,链接 7 天有效。

## 数据统计(stats.html)

单届或全部届汇总:选手战绩表(胜场、小局、胜率、名次)、职业登场占比(按选手点选查看个人使用率),支持导出 PNG 图片和文本。

## 本地运行

前端是纯 HTML/CSS/JS,不需要构建工具。启动:

```bash
npm start
```

默认地址是 http://localhost:8000,也可以用 `PORT=3000 npm start` 或 `node server.js 3000` 换端口。未配置 OSS 环境变量时,数据落在浏览器 IndexedDB,登录等账号接口走进程内开发存储,适合本地体验。此形态即**本地超管模式**:同时免登录墙——匿名打开即以超管身份浏览与编辑(画布/届/系列全开),权限仅作用于本机浏览器,不产生任何服务端写入;配置了 OSS 的部署不受影响,登录墙照常。

短信登录走阿里云号码认证服务的「短信认证服务」(`@alicloud/dypnsapi20170525`,首个外部运行时依赖,lazy require 缺库不阻断启动;官方签名/模板,个人无需自有短信签名):

- `SMS_SIGN_NAME` / `SMS_TEMPLATE_CODE`:控制台「系统赠送签名/模板」的签名名称与模板 CODE,两者配齐才算真通道开通(未配置时发送接口返回明确报错,站点其余功能不受影响)
- `SMS_TEMPLATE_PARAM`:可选,模板参数整体覆盖——模板变量名为 `${code}` 时无需配置(默认 `{"code":"##code##"}`);若赠送模板变量是 `${content}` 等其他名字,按模板正文填如 `{"content":"您的验证码为##code##,5分钟内有效"}`(整串须为合法 JSON,`##code##` 为平台验码占位符)
- `SMS_ACCESS_KEY_ID` / `SMS_ACCESS_KEY_SECRET`:独立的短信 AK(建议与 OSS 分权,如仅授 AliyunDypnsFullAccess 的专用 RAM 用户);缺省回落复用 `OSS_ACCESS_KEY_ID` / `OSS_ACCESS_KEY_SECRET`
- `AUTH_DEV_SMS_CODE`:开发后门验证码——单码(如 `123456`)或 `phone:code` 逗号列表;显式配置即最高优先(本地 .env 配齐签名/模板也不影响开发/E2E 走后门),`NODE_ENV=production` 时一律失效(生产仍勿配置);真发联调时临时注释本行
- `SESSION_SECRET`:登录会话签名密钥,生产必须固定(不设则每次重启全员掉线)
- `SUPER_ADMIN_USERNAMES` / `SUPER_ADMIN_PHONES`:超管名单(见上文账号与权限)

防骚扰参数:6 位码 5 分钟有效,同手机号 120 秒一条、每日 10 条,同 IP 每日 20 条,每码验错 5 次作废。真通道为「平台生成码+服务端校验」:验证码由 dypns 生成、经 CheckSmsVerifyCode 校验,码明文不经过本站,本地仅存发送记录做过期与尝试计数;开发/注入模式才走本地生成+进程内随机盐哈希比对(单实例内存态,多实例部署前需外置)。

## 数据怎么存

浏览器本地模式下数据存在 IndexedDB;部署后,`server.js` 同时提供静态站点和 `api/` 接口,比赛数据写入阿里云 OSS 的 `data.json`、选手账号写入 `users.json`、邀请码写入 `invite-codes.json`、图片写入 `images/`,任何设备打开网址看到的都是同一份内容。`data.json` 内是"系列 → 届"两级:顶层 `series` 数组存系列(名称、简介、创建者),每届 tournament 携带 `seriesId` 指向所属系列、`createdBy` 记录创建者(归属判定依据,由服务端盖章);没有系列的届显示在"未分组"。三类 JSON 文件每次写入前都会自动备份到 `backups/`(各保留 20 份;后台手工快照为 `manual-` 前缀,永不自动清理),操作审计按月追加。登录会话是签名 httpOnly cookie(30 天),改密码即全网下线;短信验证码与限速计数只在进程内存,重启即清。图片上传以文件魔数校验类型(PNG/JPEG/WebP/GIF),不信任客户端声明。阿里云 ECS 部署步骤见 [`deploy/README.md`](deploy/README.md);升级到系列赛版本时,上线先在服务器跑 `node scripts/migrate-series.js --dry` 预览、确认后去掉 `--dry` 实跑(存量届挂入默认系列"历届比赛"),再启动/重启服务——不迁移存量届会全部落在"未分组"且仅超管可编辑。

## 代码结构

- `canvas-model.js`:赛程画布的数据模型(点阵几何与连接点路由的唯一真源、卡片坐标、晋级流向解析、比分与名次派生、卡组继承、卡组提交窗口判定),浏览器/Node 双端可用,有单元测试
- `canvas-history.js`:画布编辑的撤销/重做历史栈(纯数据双栈,上限 10 步),浏览器/Node 双端可用,有单元测试
- `common.js`:存储层(IndexedDB/云端适配、写前合并)、页头/侧栏(桌面侧栏/移动端底部 tab 栏,按页生成页头控件)/弹窗/灯箱/toast、登录会话与登录墙守卫(无会话跳登录页),跨文件共享工具(`window.TournamentUtils`)
- `bracket.js` + `canvas-editor.js` + `list.js`:比赛页渲染与画布交互(点阵拖拽、六连接点连线、箭头连线渲染、滚轮与双指捏合缩放、撤销/重做、查找定位、公示锁),以及同页的画布/列表双视图切换
- `home.js`:主页总览工作台(当前对阵/战报/接下来的数据派生与按系列分组的比赛总览列表)
- `players.js`:选手库页面逻辑(页头搜索过滤 + 管理员新增)
- `me.js` + `my-decks.js` + `my-tourneys.js` + `profile.js`:选手中心(四标签页:我的对局/我的比赛/资料与账号/发码中心;me.js 统一登录守卫、tab 归属门与 hash 路由,功能模块逻辑各自独立)
- `stats.js`:数据统计页
- `score-stage.js`:OBS 比分舞台(登录会话读 /api/data,10 秒轮询;401 时整页登录提示)
- `vs-poster/`:海报生成器(状态管理、选手选择器、5 版式 SVG 生成、PNG 导出、OBS 舞台)
- `login.html` + `login.js`:独立登录页(手机验证码/账号密码双 tab,发送倒计时)
- `admin.html` + `admin.js`:超管后台独立页(不引 common.js;审计流水/账号与邀请码/比赛状态/健康与备份四块,封禁与管理员降级)
- `server.js`:静态站点 + `/api/*` 一体化服务
- `api/`:`data`(workspace 读写,PUT 走归属守卫)、`upload`(图片)、`poster-stage`(OBS 舞台)、`health`(健康检查)、`session`(签名会话 cookie)+ `account`(账号/短信登录/填码跃迁/绑手机)、`auth`(requireUser/requireRole 会话与角色门)、`rbac`(角色判定唯一真源,env 超管升格)、`acl`(资源归属判定与整库写守卫,createdBy 服务端盖章)、`admin`(/api/admin/* 超管后台,前缀分发)、`sms`(验证码服务与防骚扰限速)、`codes`(发码中心)、`decks`(选手卡组提交)、`signup`(报名)、`helpers`(三态存储与请求体解析)、`workspace-lock`(读-改-写互斥)、`oss`(存储/备份/审计)、`dev-store`(无 OSS 时的开发内存)
- `scripts/`:`gen-invite`(邀请码命令行生成/绑定/查询,日常已由发码中心替代)、`restore-data`(备份恢复)、`read-audit`(审计查看)、`migrate-series`(存量届挂默认系列的一次性幂等迁移,`--dry` 预览)、`backfill-oss-cache`(存量图片补缓存头)
