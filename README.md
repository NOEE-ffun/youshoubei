# 右手杯——8 人 BO3 双败淘汰赛制网站

这个网站服务一场 8 人卡牌比赛,如今是一个功能完整的小型 web 应用:办赛、看赛、交卡组、做海报都在浏览器里完成。部署后数据存云端,任何设备打开网址看到同一份内容。访客只能看;主办方输入管理口令(或注册管理员账号)后才能编辑;选手凭邀请码注册账号,可以自助维护个人资料、在提交窗口内上报自己的卡组。

> 本项目代码以 [MIT](LICENSE) 许可开源。`icons/classes/` 下的职业图标素材来自《Shadowverse: Worlds Beyond》官网,版权归 Cygames 所有,不在 MIT 许可范围内,仅供个人非盈利赛事使用。

打开网站先到总览工作台(index.html):当前对阵、最新战报、接下来三块一眼看清赛事进展;标题旁可切换正在显示的比赛,页面下方的"比赛总览"列出全部已创建比赛及其状况(点击行即切换),底部是各功能板块的快捷入口。全站配色为 Gruvbox 色板,浅色/深色双主题。

## 比赛(schedule.html)

主办方的工作台。赛程按标准双败淘汰赛排布,一共 14 场:胜者组四分之一决赛四场、半决赛两场、决赛一场;败者组第一轮两场、第二轮两场、半决赛一场、决赛一场,最后是总决赛。胜者组决赛的败者进入败者组决赛。胜者组决赛、败者组决赛和总决赛采用 BO5,其余对局为 BO3。

整个赛程铺在一张无限画布上:对局卡片按 28px 点阵定位(每卡占 10×6 个点,拖拽、方向键逐点微调,可自由摆放),Ctrl/⌘+滚轮缩放,也可以切换成滚轮直接缩放的模式;触屏设备支持单指平移、双指捏合缩放,缩放级别会记住,下次打开不用重新放大。卡片之间有带箭头的曲线标出胜者组和败者组的晋级流向。编辑时画布显示无限延伸的点阵背景并隐藏赛事背景图;连线从卡片连接点拖出——每卡六个连接点,上排默认输出胜者、接入 A 位,下排默认输出败者、接入 B 位,也可在卡片设置里自定义取哪个出口;连线端点随卡片移动自动跟随。编辑过程可以撤销/重做(⌘/Ctrl+Z 与工具栏按钮,保留最近 10 步),误删的对局连同它的比分和卡组一起找回;改动未保存时保存按钮亮圆点,此时关闭页面会弹出确认。填完比分,晋级名单和最终名次自动更新,不需要手动安排下一轮;改掉旧比分,后面的对位也会自动重算。总决赛结束后显示冠军、亚军、季军。页头的"切换比赛"下拉可以切换查看任意一届,往届比赛也从这里回看。画布与赛程列表是同一页的两种视图:顶栏按钮随时切换,列表按阶段分组展示全部场次(桌面查场次更快);窄屏默认进列表(画布缩得太小不可读),选择会记住。

每张卡片下方是职业卡组行:双方各自的职业图标并排,点图标跳转对应的卡组外链。选手没有为某场比赛提交新卡组时,自动继承他上一场的卡组(沿晋级链派生,数据不复制)。

## 选手与账号

- **选手库(players.html)**:管理跨届通用的全局选手——名字、头像、赛前垃圾话、专属颜色、队伍 ID 和队标图。垃圾话和颜色会跟着选手进海报。删除选手不影响历史比赛记录。页头有选手搜索(按名称/队伍 ID 实时过滤,全员可用);新增选手也在页头,仅管理员可见。
- **选手中心(me.html)**:登录选手的自助专区,三个标签页合一——**我的对局**(卡组提交窗口:管理员在赛事设置里配置提交开关,可设每日循环时段如每天 09:00–17:00 自动开闭,也可随时手动开关;开关开启期间,选手看到自己所有已确定的场次,逐场提交职业、卡组名称和卡组外链,可反复修改;未开始的场次,已提交的卡组对其他人隐藏(画布上显示待公示锁),开关关闭即全员公示;比赛一旦录了比分,该场卡组锁定;没提交的场次沿用继承)、**我的比赛**(自助报名:管理员开放报名后一键报名或取消,已被指派上场的不能自助退赛;开放报名的届在前,已参加过的在后,报名池并入比赛页的"选手名单")、**资料与账号**(自助修改头像、昵称、队伍 ID、队标、垃圾话和海报颜色,也能改密码;账号名只用于登录,展示名随时可改)。未登录时整页是统一登录引导;侧栏入口与左下角头像按钮都进这里,旧地址(my-decks / my-tourneys / profile)自动跳转到对应标签页。

账号体系用邀请码注册:管理员生成空白码(新选手,注册即以用户名建选手)或绑定码(老选手,登录即继承其全部历史数据),发码即发身份;管理员引导码由环境变量 `ADMIN_INVITE_CODE` 单独控制。安全规则:登录身份为选手时管理口令一律失效——即使浏览器里残留有效口令,前后端都拒绝一切管理操作。

## 海报生成器(poster.html)

赛前做 VS 海报。左右选手直接从主站选手库选择,名字、头像、队标、颜色、垃圾话一并带出,也能对颜色做临时微调;比赛信息(名称、阶段、局数、日期、场馆)自由填写。内置 5 种版式(撕裂分屏 / 像素街机 / 极简刊头 / 魔纹华饰 / 赛博霓虹)共 11 套主题,预览和导出共用同一份 SVG,所见即所得,可导出 1080p/2K/4K 的 PNG。"生成 OBS 源"按钮调服务器接口生成短链地址,粘贴到 OBS 的浏览器来源即可在直播中展示,链接 7 天有效。

## 数据统计(stats.html)

单届或全部届汇总:选手战绩表(胜场、小局、胜率、名次)、职业登场占比(按选手点选查看个人使用率),支持导出 PNG 图片和文本。

## 本地运行

前端是纯 HTML/CSS/JS,不需要构建工具。启动:

```bash
npm start
```

默认地址是 http://localhost:8000,也可以用 `PORT=3000 npm start` 或 `node server.js 3000` 换端口。未配置 OSS 环境变量时,数据落在浏览器 IndexedDB,登录等账号接口走进程内开发存储,适合本地体验。

## 数据怎么存

浏览器本地模式下数据存在 IndexedDB;部署后,`server.js` 同时提供静态站点和 `api/` 接口,比赛数据写入阿里云 OSS 的 `data.json`、选手账号写入 `users.json`、邀请码写入 `invite-codes.json`、图片写入 `images/`,任何设备打开网址看到的都是同一份内容。三类 JSON 文件每次写入前都会自动备份到 `backups/`(各保留 20 份),操作审计按月追加。管理口令只存 sessionStorage;登录会话是签名 httpOnly cookie,改密码即全网下线。图片上传以文件魔数校验类型(PNG/JPEG/WebP/GIF),不信任客户端声明。阿里云 ECS 部署步骤见 [`deploy/README.md`](deploy/README.md)。

## 代码结构

- `canvas-model.js`:赛程画布的数据模型(点阵几何与连接点路由的唯一真源、卡片坐标、晋级流向解析、比分与名次派生、卡组继承、卡组提交窗口判定),浏览器/Node 双端可用,有单元测试
- `canvas-history.js`:画布编辑的撤销/重做历史栈(纯数据双栈,上限 10 步),浏览器/Node 双端可用,有单元测试
- `common.js`:存储层(IndexedDB/云端适配、写前合并)、页头/侧栏(桌面侧栏/移动端底部 tab 栏,按页生成页头控件)/弹窗/灯箱/toast、登录会话与邀请码注册弹窗,跨文件共享工具(`window.TournamentUtils`)
- `bracket.js` + `canvas-editor.js` + `list.js`:比赛页渲染与画布交互(点阵拖拽、六连接点连线、箭头连线渲染、滚轮与双指捏合缩放、撤销/重做、查找定位、公示锁),以及同页的画布/列表双视图切换
- `home.js`:主页总览工作台(当前对阵/战报/接下来的数据派生与比赛总览列表)
- `players.js`:选手库页面逻辑(页头搜索过滤 + 管理员新增)
- `me.js` + `my-decks.js` + `my-tourneys.js` + `profile.js`:选手中心(三标签页;me.js 统一登录守卫与 hash 路由,三个功能模块逻辑各自独立)
- `stats.js`:数据统计页
- `score-stage.js`:OBS 比分舞台(公开数据 10 秒轮询)
- `vs-poster/`:海报生成器(状态管理、选手选择器、5 版式 SVG 生成、PNG 导出、OBS 舞台)
- `server.js`:静态站点 + `/api/*` 一体化服务
- `api/`:`data`(workspace 读写)、`upload`(图片)、`poster-stage`(OBS 舞台)、`session` + `account`(签名会话与账号体系)、`decks`(选手卡组提交)、`signup`(报名)、`helpers`(三态存储与请求体解析)、`workspace-lock`(读-改-写互斥)、`oss`(存储/备份/审计)、`dev-store`(无 OSS 时的开发内存)
- `scripts/`:`gen-invite`(邀请码生成/绑定/查询)、`restore-data`(备份恢复)、`read-audit`(审计查看)、`backfill-oss-cache`(存量图片补缓存头)

## 测试

```bash
npm test          # 66 项单元测试
npm run test:e2e  # Playwright 端到端 20 条(含登录、卡组提交、报名、画布撤销、移动端适配、画布边界回归全链路)
```

单元测试覆盖画布解析与晋级流向、画布编辑历史栈(撤销/重做)、卡组继承、剪贴板重映射、选手字段归一化、OSS 重试与备份、账号与会话安全(含"选手带口令必被拒"回归)、卡组提交窗口语义、服务冒烟和海报接口。端到端测试跑通完整链路:管理员布置赛事 → 选手注册提交卡组 → 公示隐藏与解锁;移动端用例覆盖画布/列表双视图、底部 tab 栏、触控目标、缩放持久化与双指捏合。
